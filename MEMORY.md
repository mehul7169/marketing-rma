## Conventions
- Counts, filters, cohorts and badges import from `src/lib/leads/lifecycleDefinitions.ts`. Stage = `pipeline_stage`. Calls Booked = `call_booked_at` in range (not `call_confirmed`). Showups = `call_showed` + `call_showed_at` in range. Follow-up colour is render-time IST (`followUpState`), never stored.
- `stamp()` still writes `stage` (post-call values for StageBadge). It does not write `action_status`, `lifecycle_status`, or `call_confirmed`. Those columns stay until a drop migration after a week of verification.
- Lifecycle writes go only through `updateLeadLifecycle` / `planLifecycle` (README "Lead lifecycle writes"). Deal writes go through `updateDeal` / `planDeal` (`src/lib/deals/dealLifecycle.ts`). Both commit lead + activity via `apply_lead_change` (migration 009). Field edits log `field_edited`; drawer recording stays on `saveLeadActions`. Post-call status / won / lost / next step are deal actions only.
- A deal is `call_showed = true`. Work Queue sets `excludeShowed` on every tab, count, and custom-filter path (`listFiltersForView` + `leadBelongsInView`). `/leads` does not. `/deals` lists showed leads via `showedOnly` (open/won/lost = `deal_closed` NULL/true/false). Open grouping is IST in `classifyOpenDeal`: overdue is instant `< now` (not the Work Queue calendar-day overdue). Needs next step = missing `next_step` or `next_action_at`. Drawer param is `?deal=` (`useDealDrawerParam`, same pushState/replaceState pattern as `?lead=`). Persist page key `deals`; `?deal=` is a deep link. `stamp()`/`computeStage` already maps `deal_closed`, `contract_shared`, `awaiting_payment`. Insights Activity still selects `lead_activities.type = call_attempt` only. Closing rate is still won ÷ qualified showups (`countKpi deals_closed / qualified_showups`).
- `mark_showed` sets `owner_id = actor.userId` when null. `owner_id` FKs `profiles(id)` ON DELETE SET NULL. Lost reason CHECK: `price, timing, not_a_fit, ghosted, chose_someone_else, other`. Open-deal `post_call_status` CHECK: `follow_up_call_booked, awaiting_lead_response, contract_shared, awaiting_payment` (NULL = Showed up).

## Insights
- KPI deep links (`?kpi=`) window on the milestone timestamp in IST days (`istDayStartUtcIso`/`istDayEndUtcIso`), inclusive of the last day. `?cohort=` / `?event=` still rewrite onto `kpi`. Dead leads are included.
- `lead_activities.type` is free text (no CHECK constraint); `created_by` FKs `profiles(id)`.
- `computeActionStatus` ignores its `_lastCallOutcome` arg, so `last_action` label text does not affect status.
- `*_at` milestone columns are first-set timestamps (`firstSetAt`), not last-change times.

- E2E: `e2e/*.spec.ts` need `PLAYWRIGHT_BROWSERS_PATH=$HOME/Library/Caches/ms-playwright` and E2E_* creds (map from TEST_* in .env). Start dev with `WATCHPACK_POLLING=true` + `ulimit -n 10240`. TEST_ADMIN_EMAIL is NOT a platform admin (preview e2e skips).

- Home / Slack / `/leads?kpi=` / Meta funnel Calls Booked + Showups all use `lifecycleDefinitions` KPIs. Meta table totals are still facebook+quickform attributed only, so they will not equal org-wide Home counts.
- Lead → ad attribution: `createLeadAdResolver` in `src/lib/meta/funnelOutcomes.ts`. facebook and quickform leads carry the ad NAME in `utm_content` (0 match by id), and names like "London 1/2/3" repeat across campaigns. Same-named ads resolve to the highest-spend ad in range.
- `meta_ads_daily.landing_page_views` added and backfilled 2026-09-28 (migration 007, 806 rows, 0 mismatches vs `actions`).
- `call_showed` is manual only. Recordings are Fathom share links (`fathom.video/share/...`). There's no Fathom or cal.com integration or key in `.env`.

- There's no booking activity type. Work Queue "Qualified" = qualify + book_call. Self-serve cal.com bookings never write a `call_attempt`. Setter "Calls Booked" (Insights setter table) = qualified row within 5 min of `call_booked_at`, once per lead (user decision 2026-09-29). Headline Calls Booked KPI is `call_booked_at` in range.
- Filter persistence lives in `table_views.config.filters[orgId]` (user chose no new table). Named saved views live in `config.namedFilters[orgId]` (personal + `shared: true` for the org; admins edit shared). Don't add a `filters` column. `src/lib/leads/listFilterParams.ts` is the single parse/build path for `/leads` URLs. Custom filter: `?cf=` base64url JSON, registry in `filterFields.ts`, query translation in `customFilterQuery.ts`. Deal/Dead/Dead reason yield hide-dead; Form Qualified yields hide-form-unqualified. "Is not" is null-safe. JSON `custom_fields->>key` filters may scan (~2k rows is fine; no extra index added).
- Crons: Vercel Cron in `vercel.json` (UTC schedules). Auth is `assertCronSecret`, and Vercel sends `Authorization: Bearer $CRON_SECRET`. Runs are logged via `logCronRun`, which then calls `reportCronResult` (Slack to `SLACK_DAILY_SUMMARY_WEBHOOK_URL`; never hardcode). Hourly jobs: 3 consecutive errors; daily-summary / deals-digest / adspend-sheet: 1 failure. Alert once, then every 24h while down, then one recovery. State table `cron_alert_state` (migration 010 — owner applies). Meta token expiry copy is special-cased. Admin banner on `/` and `/meta-ads` when meta-ads is failing or `meta_ads_daily` is >2 IST days stale. The daily digest `30 14 * * *` (8 PM IST) reuses page query functions. Deal follow-ups digest `30 3 * * *` (9 AM IST) reuses `listFiltersForDeals` + `classifyOpenDeal` / `computeDealMetrics`. Digest webhook `SLACK_DEALS_DIGEST_WEBHOOK_URL` with fallback to the daily-summary webhook. Don't write parallel queries. Test with `?dry_run=1` and don't spam the live webhook.
- `form_qualified` = the website form's verdict (tag only). `qualified*` = the setter's decision only. The backfill ran in prod on 2026-10-27, 11:16–11:51 UTC, as raw SQL with no `updated_at` trigger, so rows don't show the change. The Slack no-booking nudge is RMA-only (org filter) and uses form_qualified OR qualified.
- The org table is `organizations` (not `orgs`). `profiles` has id, email, role, is_platform_admin, and no name column.
